# P6: Own the stack (0.5.x to 0.7.x)

**Status:** not started.

## Goal

Reach the dependency goal: libc, the kernel's headers, libtam, code in
this repository, and Mesa for the GPU. Each step replaces one library with
libtam code and leaves tam-pane working on a daily-driver system.

## Versions

- **0.5.x Input.** Read evdev devices directly through the kernel's
  input headers, with libtam owning device discovery, keymaps and
  repeat. This replaces libinput and xkbcommon. Keymaps come from a
  compact compiled format generated at build time, not from parsing XKB
  sources at runtime.
- **0.6.x Wayland protocol.** A libtam Wayland wire implementation:
  socket, message framing, object ids and file-descriptor passing, with
  protocol code generated by our own scanner from the XML files. This
  replaces libwayland-server.
- **0.7.x Backend and rendering.** libtam's `tam_display` and
  `tam_display_session` inspect connectors, CRTCs and planes, blank and
  restore the console through atomic commits, and observe the seat. They
  are built for console handoff, not for a compositor: they take no
  device control (no TakeControl/TakeDevice, no KD_GRAPHICS) and have no
  buffer allocation, page flips, vblank events, cursor planes, mode
  setting, hotplug or input (libtam review R2). A compositor mode needs a
  new libtam layer, then a full output backend that renders with Mesa GBM
  and EGL. This replaces wlroots, pixman, libdrm and libseat.

Decision (Fred, 2026-11-25): libtam's shared Wayland wire module and
evdev keymaps wait until after Tamlinux 0.7.0. libtam's 0.7 refactor
(libtam `plans/P1-0.7-refactor.md`) covers the core, process, socket and
terminal primitives first.

## Acceptance

- After each step, `readelf -d build/tam-pane` lists one library fewer, and
  a working day on the new build passes without regressions.
- At 0.7.x the NEEDED list is libc, libm, and Mesa's libEGL, libGLESv2 and
  libgbm.

## Dependencies

- Removes, in order: libinput and xkbcommon, then libwayland-server, then
  wlroots and everything it pulls in.

## Risks

- **Size of the work.** Each step is a major project. Every step ships on
  its own, so tam-pane is never left half-migrated.
- **Hardware coverage.** libinput carries years of device quirks. Start
  with the devices on Fred's machines and record the quirks we add in
  `arch/`.

## Open points

- Whether libtam or tam-pane owns the Wayland wire code. It belongs in
  libtam if other Tamlinux programs will use it.
